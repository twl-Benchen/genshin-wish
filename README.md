# 原神期望抽數計算
**連結：https://twl-benchen.github.io/genshin-wish/**

<img width="1293" height="1665" alt="twl-benchen github io_genshin-wish_" src="https://github.com/user-attachments/assets/32f8c17f-9a7e-4125-a551-444c4b5329bf" />
輸入想抽的角色命座、武器精煉、目前墊了幾抽和手上的資源，算出完整的抽數機率分布：期望抽數、一半機率和九成機率要幾抽、最壞情況，以及手上的原石夠不夠。

結果是精確計算出來的，不是隨機模擬，每次算出來都一樣。

本專案與米哈遊官方無關，逐抽機率採用玩家社群擬合的模型，結果僅供參考。

## 功能

### 設定目標

- **角色活動祈願**：想抽 0 到 7 隻 UP 角色 (7 隻是滿命)。按「+ 另一個角色」可以同時設兩隻 UP，對應「角色活動祈願」和「角色活動祈願-2」。
- **武器活動祈願**：想抽 0 到 5 把定軌武器 (5 把是精 5)。按「+ 另一把武器」可以兩把 UP 武器都要，並選擇定軌方式：最佳策略、定軌缺得多的那把、分開抽。
- 沒有選目標的卡池，下面的墊抽、保底設定整塊變淡，一眼看出哪些設定不會影響結果。

### 墊抽與保底狀態

- **已墊抽數**：可以直接輸入，也可以按「算抽數」從祈願歷史紀錄推算。
- **明光計數** (0 到 3) 和**命定值** (0 到 1) 用分段按鈕選，手機上也點得準。
- **大保底**：角色池是上次五星歪成常駐，武器池是上一把五星是常駐武器。勾角色池大保底時，明光計數會自動調成至少 1。
- 每個設定旁的 i 圖示點開有說明，滑鼠移上去也會顯示。

### 算抽數 (祈願歷史紀錄)

- 打開一個仿遊戲的祈願歷史紀錄視窗，拖動或點頁數調成跟遊戲裡一樣，再點上一顆五星在第幾列，自動換算已經墊了幾抽。
- 同時可以標記那顆五星是 UP 還是常駐，順便設好大保底。
- 武器池還可以標記是定軌那把、另一把 UP 或常駐武器，以及是這一期還是之前的卡池抽到的，自動設好命定值和大保底。

### 兩把 UP 武器的定軌建議

- 武器欄下方會依目前的目標、命定值和大保底，告訴你現在該維持定軌、取消再重新定軌，還是改定軌另一把，以及三種抽法平均差幾抽。

### 手上的資源

- 填原石、糾纏之緣、無主星輝，自動換算可抽幾抽。
- 已經自己算好總抽數的話，直接改「可抽」那格就好。原本逐項填的數字會記住，隨時可以改回來。

### 課金試算

- 展開「課金試算」，用 −/+ 調整課幾單，每次 0.5 單。一單是 NT$3,290 那一檔，平常實拿 8,080 創世結晶，可以勾選第一單是首儲雙倍。
- 摘要卡的達成率、里程碑表、圖表都會即時跟著變。
- 圖表用虛線標出課金前的預算，課金買到的那段塗深色。
- 有設定課金時，會反推一半機率、九成機率至少要課幾單和金額，點單數可以直接套用。

### 星輝返還

- 展開「星輝返還」，填四星角色大約幾成已經滿命，以及 8 位常駐五星各有幾命。
- 開啟後結果改用「實付抽數」，扣掉抽卡途中返還的星輝換成的抽數，摘要下方會寫扣掉了大約幾抽。

### 結果

- **摘要卡**：期望抽數 (含原石換算)、一半機率、九成機率 (含最壞情況)、預算達成率。
- **幾抽內能達成目標**：累積達成機率曲線，標出 50%、90% 和預算線。滑鼠移上去 (手機用手指拖曳) 可以看任意抽數的達成機率。
- **每個里程碑**：每隻角色、每把武器的累計期望抽數、九成機率、最多幾抽，以及「N 抽內達成率」(N 是你的可抽數)。手機上會拿掉進度條，不用左右滑就看得到達成率。可以按住左邊的點點拖動調整抽的順序，例如先抽 3 隻角色再抽武器，看到後面機率太低就知道不用抽了。

### 抽卡規則頁

- **下一顆五星的等待**：角色池、武器池各三種角度看出金機率，分別是條件機率、首金分布、累計出金率，會套用目前的墊抽。
- **首個 UP**：抽到第一隻 UP 角色 (或第一把定軌武器) 要幾抽的分布，會出現兩個峰，左邊是第一顆五星就是 UP，右邊是先歪了再等一顆。會套用目前的墊抽和保底狀態。
- 列出計算用的所有規則和數字。

### 分享結果

- 產生一張仿遊戲視窗的結果圖，可選橫式或直式，裡面有目標、資源、重點數字、曲線、里程碑表和網站 QR code。
- 可以下載圖片，手機支援的話也能直接用系統分享。

### 其他

- 所有輸入都存在瀏覽器裡，下次打開還在。
- 支援深色模式，手機版面是單欄。
- 網址加 `#rules` 會直接打開抽卡規則頁。

## 特別設計

### 精確計算，不是模擬

很多抽卡計算器用隨機模擬跑幾萬次，結果每次都有一點不同。這裡把抽卡過程寫成馬可夫鏈：從墊抽推出下一顆五星要幾抽的分布，每出一顆五星做一次狀態轉移，抽數的分布用卷積累加。最後得到完整的機率分布，期望值、分位數、達成率都是精確值。

`test.js` 會拿精確計算跟 30 萬次隨機模擬比對，確認兩邊對得上。

### 捕獲明光用保守模型

5.0 加入的捕獲明光，官方只公布小保底綜合 UP 機率 55%，以及連續三次「先歪再靠大保底」之後必定觸發，中間各階段的機率沒有公開。網頁用「計數到 3 才必定觸發，其他時候照 50/50」的保守模型，長期勝率約 55.6%，最接近官方的 55%。規劃時寧可多估一點抽數。

### 武器池的最佳定軌策略

5.0 起命定值上限是 1，兩把 UP 武器都要時，歪到常駐後先取消定軌再重新定軌，命定值歸 0 但大保底還在，下一把五星一定是兩把 UP 之一。網頁用動態規劃在每把五星之前選最划算的做法，期望值跟影片分析的數字一致。

### 兩個角色池共享狀態

「角色活動祈願」和「角色活動祈願-2」共享墊抽、大保底和明光計數，每顆五星前都能自己選在哪個池子抽，所以總抽數只看總共要幾隻 UP。兩隻角色的先後順序只影響里程碑表每一列是誰。

### 角色和武器分開算再合併

角色池和武器池的保底互不影響，所以兩邊各自算出分布再卷積。調整抽的順序只是重新組合，不用重算整條鏈。

### 調課金不重算機率

預算不影響機率分布，只影響達成率和圖上的預算線。調整課金時直接沿用算好的分布，連按 + 也不會卡。

### 分享功能的小細節

- 網站 QR code 直接寫在程式裡，不載入外部函式庫。
- 分享按鈕的程式名稱刻意避開 `share` 這類字，因為廣告攔截套件會把它當成社群分享按鈕藏起來。
- 產生圖片前會先等中文字型載完，最多等 3 秒，載不到就用備用字型。
